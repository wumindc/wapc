## 1. 背景与目标

### 1.1 产品简介

WAPC（本机 AI 编程工具 Token 观测器）是一款基于 **Tauri v2 + React + TypeScript** 的桌面应用，用于本地扫描、统计和管理用户使用各类 AI 编程工具（Claude Code、Codex、Gemini CLI 等）产生的 Token 使用数据，全程数据不上传。

### 1.2 现存问题

| 编号 | 问题 | 影响 |
|---|---|---|
| P1 | 响应式自适应覆盖不完整，部分页面在小窗口下无法正常操作 | 用户体验损坏 |
| P2 | 移动端（< 768px）侧边栏直接隐藏，无替代导航入口 | 小尺寸窗口下无法使用 |
| P3 | 现有菜单结构扁平，MCP/Skills/Plugin 均藏在"资源中心"，入口不清晰 | 功能发现性低 |
| P4 | MCP、Skills、Plugin 使用同一页面展示，体验与场景不匹配 | 各模块价值无法体现 |
| P5 | 支持工具页面设计旧，缺少对新工具（Trae/Qoder/Kiro/Antigravity IDE）的展示 | 产品定位感弱 |
| P6 | "导出"功能单独成菜单，"导入"功能藏在资源中心深处 | 数据同步功能分散 |

### 1.3 本次目标

1. **建立全局响应式规范**：明确三档断点规则，统一移动端导航方案
2. **重构导航信息架构**：按功能域分组，提升菜单的发现性和层级清晰度
3. **每个功能模块独立设计需求**：MCP / Skills / Plugin / 支持工具各自按场景设计，不共用页面
4. **补全新工具支持**：在 UI 层呈现 9 款支持工具，后端逐步跟进

## 2. 全局规范

### 2.1 响应式断点规范

| 断点名 | 宽度范围 | 侧边栏行为 | 内容布局 |
|---|---|---|---|
| 移动端 | < 768px | **隐藏**，Header 显示汉堡菜单 → 点击弹出 Drawer | 单列 |
| 平板端 | 768px ~ 1023px | **折叠**图标模式（宽 72px，仅图标） | 单列为主 |
| 桌面端 | ≥ 1024px | **完整展开**（宽 220px，图标+文字） | 双列 / 多列 |

### 2.2 移动端导航（新增需求）

- **触发方式**：Header 左上角汉堡菜单按钮，仅在 `< md`（< 768px）尺寸下显示
- **Drawer 展开**：侧边栏以 Drawer 形式从左侧滑入，动画 `translateX(-100%) → 0`，时长 250ms ease-out
- **遮罩**：Drawer 打开时，右侧内容区出现 `rgba(0,0,0,0.4)` 半透明遮罩
- **关闭方式**：点击遮罩 / 点击导航项 / 点击关闭按钮
- **尺寸**：Drawer 宽度 280px（或屏幕宽度 85%，取较小值）

### 2.3 亮色 / 暗色模式规范

- **现有机制保持不变**：`ThemeProvider` 管理 `light / dark / system` 三态
- **新增要求**：所有新增页面的 CSS 颜色必须使用 Design Token 变量，禁止硬编码颜色值
- **Design Token 变量**：参考 `index.css` 中已定义的 `--color-*` 系列

### 2.4 表格响应式规范

所有包含数据表格的区域，必须使用 `overflow-x-auto` 容器包裹，禁止出现布局撑破问题。

### 2.5 卡片规范

所有卡片使用 `.card` 类（`bg-surface + border + border-radius + box-shadow`），内边距统一为 `p-4 sm:p-[18px]`。

**用户核心问题**：

```
└────────────────────────┴────────────────────────────────────┘
```

#### 4.4.2 MCP 列表（左侧）

**列表项展示**：
- MCP 名称
- 状态指示点：🟢 正常（全部工具启用）/ 🟡 部分（仅部分工具启用）/ 🔴 异常（解析失败）/ ⚪ 未启用
- 简要标注：启用的工具名称（最多显示 2 个，超出显示 +N）

**筛选功能**：
- 工具筛选：全部 / Claude Code / Codex / Gemini CLI / ...（来自实际数据）
- 状态筛选：全部 / 正常 / 部分 / 异常
- 关键字搜索：按 MCP 名称模糊搜索

**数据来源**：`snapshot.resources` 中 `kind = "mcp_server"` 的资源

#### 4.4.3 MCP 详情面板（右侧）

| 区域 | 内容 |
|---|---|
| 基本信息 | 名称、kind、scope、来源工具、confidence、是否脱敏 |
| 工具支持矩阵 | 以表格形式展示"此 MCP × 各工具"的启用状态 |
| 配置预览 | 展示 `payload_json` 内容（格式化 JSON），已脱敏的显示占位符 |
| 历史变更 | 最近 4 条变更记录（change_id、操作类型、时间） |
| 操作按钮 | [同步到其他工具] → 触发同步流程 / [编辑配置]（如可写） |

#### 4.4.4 跨工具同步流程

1. 用户点击 [同步到其他工具]
2. 弹出目标工具选择器（Checkbox 列表）
3. 点击 [生成同步预览] → 展示写入 Diff
4. 确认风险提示 → 点击 [确认应用]
5. 展示同步结果

**调用 API**：`plan_sync` → `apply_sync`（复用现有 Rust 后端）

#### 4.4.5 响应式

- 桌面端：左右 Master-Detail 布局，左侧固定 300px，右侧 flex-1
- 平板端：左侧列表 + 右侧面板堆叠为单列，点击列表项后滑入详情
- 移动端：仅显示列表，点击后进入详情页（全屏）

## 7. 非功能性要求

### 7.1 性能

- 页面切换响应时间 < 300ms（不含网络请求）
- 大列表（> 100 项）使用虚拟滚动或分页，避免一次性渲染
- 图片/图标使用 SVG，避免加载外部资源

### 7.2 安全与隐私

- 所有页面展示的路径信息均来自本机 snapshot，不上传
- `payload_json` 中已脱敏的字段（`redacted = true`）必须以占位符展示，不展示原始值
- Deep Link 导入流程必须经过"预览 → 确认"两步，不允许跳过直接导入

### 7.3 无障碍

- 所有交互元素必须有 `aria-label` 或可见文字标签
- 键盘可导航：Tab 键可访问所有交互元素
- 颜色对比度满足 WCAG AA 标准（正文 ≥ 4.5:1，大文字 ≥ 3:1）

### 7.4 国际化

- 当前仅支持中文，所有文案使用中文
- 代码中不要硬编码中文字符串到逻辑层（仅在 JSX 展示层使用）
