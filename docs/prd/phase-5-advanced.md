# Phase 5 PRD — 进阶与发布(Advanced & Release)

> 状态:草案 v1,待审核 · 最后更新:2026-06-05 · 写入风险:混合
> 上游:[PRD 总览](README.md)

## 1. 背景与问题

核心闭环(观测 + 管理 + 同步)在 Phase 1–4 完成。Phase 5 是"放大与收尾":让资源更易分发、让团队可用、让发布更专业。本阶段各特性相对独立,可按价值与成本择优排期,不必一次全做。

## 2. 目标 / 非目标

**目标(可拆分,按优先级)**
- G1 资源模板库:精选 MCP/Skills/指令模板,一键安全安装(走 Sync Engine)。
- G2 深链 `wapc://`:通过 URL 导入资源定义(不含密钥)。
- G3 团队脱敏报告:脱敏路径、项目别名、时间窗口汇总、可复现 fixture。
- G4 Headless 只读模式:SSH/server 场景的本地只读 dashboard。
- G5 macOS 签名与公证(发布质量)。
- G6(条件触发)macOS 稳定后再评估跨平台。

**非目标**
- 不做账号体系/云端存储/数据上传(与隐私原则冲突)。
- 不做密钥同步/托管。

## 3. 用户与场景

| Persona | 诉求 |
| --- | --- |
| 想快速上手的用户 | 从模板库一键装常用 MCP/Skill |
| 团队负责人 | 导出脱敏的成本/资源报告给团队 |
| 远程开发者 | 在 server 上只读查看本机用量 |
| 发行者 | 用户下载即用,无 Gatekeeper 拦截 |

## 4. 子特性 PRD

### 4.A 资源模板库(Template Library)

- **背景**:用户常需要相同的几个 MCP/Skill,手动找配置麻烦。
- **FR-A1** 内置/可更新的模板清单(canonical 资源,**不含密钥值**),含说明与来源。
- **FR-A2** 一键安装:选模板 → 选目标工具 → 走 Phase 4 同步流程(预览/备份/写入/回滚)。
- **FR-A3** 模板含密钥占位时,安装流程要求用户手填(不入库)。
- **FR-A4** 模板来源透明:展示出处与内容指纹,避免供应链风险。
- **AC-A** 从模板装一个 MCP 到指定工具,全程经 Sync Engine 且可回滚;模板不含任何真实密钥。

### 4.B 深链 `wapc://`(Deep Link)

- **背景**:让资源可"点链接即导入"(对标 cc-switch 的 `ccswitch://`)。
- **FR-B1** 注册 `wapc://` scheme;解析 `wapc://import?...` 导入 canonical 资源定义。
- **FR-B2** 深链**只携带资源结构,不携带密钥**;含密钥字段以占位出现,导入后按 Phase 4 流程手填。
- **FR-B3** 导入前必须展示来源与完整内容预览,用户确认才进入同步流程。
- **FR-B4** 对未知/可疑来源给出风险提示。
- **AC-B** 点击一个 `wapc://import` 链接 → 预览 → 选目标 → 安全写入;链接内若含明文密钥则拒绝并告警。

### 4.C 团队脱敏报告(Redacted Report)

- **背景**:把成本/资源情况分享给团队,但不泄露路径/项目/密钥。
- **FR-C1** 报告生成器:可选时间窗口,输出按工具/项目/模型的汇总。
- **FR-C2** 脱敏:项目路径→别名或哈希、家目录路径裁剪、绝不含正文与密钥。
- **FR-C3** 输出 Markdown/JSON,并可附"可复现 fixture"(合成数据,非真实)。
- **AC-C** 生成的报告中无真实绝对路径、无项目名(除非用户选择保留别名)、无任何密钥/正文。

### 4.D Headless 只读模式

- **背景**:server/SSH 场景没有 GUI,但想只读看用量。
- **FR-D1** 提供一个**只读**的本地 HTTP dashboard(仅监听 `127.0.0.1`,默认关闭,用户显式开启)。
- **FR-D2** 只读:仅暴露查询接口,**无任何写入/同步能力**。
- **FR-D3** 不开放外网监听;无鉴权即不绑非回环地址。
- **AC-D** 开启后本机 `127.0.0.1` 可看只读 dashboard;任何写操作接口不存在;非回环访问被拒。

### 4.E macOS 签名与公证

- **FR-E1** 发布产物用 Developer ID 签名并通过 Apple 公证。
- **FR-E2** CI 集成签名/公证步骤;发布 tag 触发。
- **FR-E3** README 发布说明更新为"下载即用"。
- **AC-E** 在干净 macOS 上下载安装,无 Gatekeeper 拦截即可启动。

### 4.F 跨平台评估(条件触发)

- **FR-F1** 仅当 macOS 版本稳定后启动;先做可行性评估(Tauri 跨平台 + 各工具在 Win/Linux 的路径差异)。
- **FR-F2** 适配矩阵补充 Windows/Linux 列。
- **AC-F** 产出跨平台可行性评估文档与适配矩阵增量(本阶段不一定实现)。

## 5. 数据模型

- 模板库:`resource_templates`(id、name、kind、payload_json 不含密钥、source、updated_at)。
- 深链导入:复用 Phase 4 同步流程,无新增持久化(导入即进入 plan)。
- 报告:无需持久化(即时生成)。

## 6. 隐私与安全(本阶段尤其关键)

- 模板/深链:**只携带结构,密钥永远占位**;导入前强制预览;可疑来源告警。
- 报告:脱敏是硬性验收项,默认最严(哈希路径、隐藏项目名)。
- Headless:默认关闭、仅回环、只读;这是最容易引入风险的特性,需安全评审。
- `privacy-audit` 增量覆盖模板来源、深链处理、报告脱敏、Headless 监听范围。

## 7. 依赖与顺序

- 模板库/深链依赖 Phase 4 同步流程。
- 报告依赖 Phase 1 价格规则与项目别名。
- 签名/公证可与任意阶段并行(发布工程)。
- 跨平台依赖 macOS 整体稳定。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 深链成为攻击面(恶意导入) | 只带结构 + 强制预览 + 拒绝明文密钥 + 来源告警 |
| Headless 暴露数据 | 默认关闭 + 仅回环 + 只读 + 安全评审 |
| 报告脱敏不彻底 | 脱敏单测 + 默认最严 + 发布前人工抽检 |
| 模板供应链风险 | 内容指纹 + 来源透明 + 仅精选 |

## 10. 优先级建议

1. **先做** E(签名公证,直接提升发布质量)与 A(模板库,放大价值)。
2. **再做** C(报告)与 B(深链)。
3. **谨慎做** D(Headless,安全成本高)。
4. **最后评估** F(跨平台)。
